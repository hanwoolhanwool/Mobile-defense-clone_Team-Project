## 진입 조건

| 확인 항목 | 현재 상태 | 착수 시 남길 기록 |
|---|---|---|
| 이전 참고 P1 완료 | 미검증 | 참고 통합 SHA·실행 증거 |
| 이전 실제 P1 완료 | 미검증 | 실제 통합 SHA·실행 증거 |
| 이번 범위·역할 | [개발 계획서](../../docs/production/DEVELOPMENT_PLAN.md)에 계획 역할 편성, 상세 사양 후속 | 정식 TASK·A/B 담당·리뷰 담당 |
| 공통 API·데이터 변경 | 미확정 | 전후 계약·양쪽 적용 순서·호환성 |
| 제공 코드·직접 작성 범위 | 미확정 | 단계별 파일·시작 조건 |
| Unreal 에셋·설정 영향 | 미검증 | 부모·참조·설정 변경과 재검수 범위 |

[역할 기준](../../docs/production/TEAM_ROLES.md)과 [공통 구현 설계](../../docs/technical/IMPLEMENTATION_SHARED.md)를 먼저 확인한다. 새 서비스가 추가되면 클라이언트·서버·저장 데이터의 책임과 기존 전투/경제 상태 연결을 정식 설계에 먼저 확정한다.

## 수업 작성 순서

이전 단계 재현 확인 → 범위/역할 확정 → 최소 API 교환 → 작은 기능 구현/통합 → 전체 회귀 검수 순서로 준비한다. 자세한 설명에는 [수업 양식](../templates/LESSON.md)을 사용한다. 미배정 작업은 담당과 선행 조건을 정한 뒤 A/B 목차에 추가한다.
