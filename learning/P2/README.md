# P2 학습 경로

**단계별 최신 기준:** [로드맵](../../docs/production/ROADMAP.md#phase-plan) · [계획/구현 차이](../../docs/production/PHASE_ALIGNMENT.md). P1 이후 서버·계정·친구 방·재접속에서도 RouteIndex·현재/최대 수·보스 마감·단일 결과/보상을 유지한다. 정식 매칭·성장·채팅/이모티콘은 서비스 범위 확정 전 후보이며 세부 담당을 임의 배정하지 않는다.

[학습 홈](../README.md) · [운영 규칙](../WORKFLOW.md) · [이전 단계](../P1/README.md)

P1 이후 서비스 단계의 학습 구조다. [개발 계획서](../../docs/production/DEVELOPMENT_PLAN.md)에 A 서버/재접속/운영·B 계정/방/보상·미니게임 각1종의 계획 역할을 편성했다. 서비스 사양·실제 담당자·상세 수업은 후속이다. 범위의 원본은 [로드맵](../../docs/production/ROADMAP.md)과 [작업 보드](../../docs/production/BOARD.md)다.

## 로비 미니게임 학습 범위

[로비 미니게임 계획](../../docs/design/COOP_META.md#lobby-minigames)의 최대 2종 구현을 포함한다. TASK-MINIGAME-01의 종류·규칙·담당 확정 후 A/B 수업과 중간 통합 순서를 작성한다. 진입·플레이·결과·로비 복귀·터치 검수를 기록하고 보상/저장 채택 시 해당 연결도 다룬다. 현재 상세 수업·코드·실행 증거는 없다.

## 진행 순서

1. [공통 준비](COMMON.md)에서 이전 결과·추가 범위·공통 API 변경·역할을 확정한다.
2. [A 경로](A/README.md)와 [B 경로](B/README.md)의 수업을 제작·재현한다.
3. [통합 검수](INTEGRATION.md)에서 이전 기능 회귀와 새 기능을 확인한다.
4. 다음 마일스톤도 같은 폴더 구조를 사용하고 각 과정의 자기 통합 SHA에서 이어간다.

이전 P1 참고 완성본을 실제 개발 브랜치에 덮어써 출발점을 맞추지 않는다. 두 과정의 커밋은 별도로 기록하고 동작·API·데이터 호환성을 대조한다.
