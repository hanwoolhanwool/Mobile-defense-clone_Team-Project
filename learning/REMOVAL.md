# 학습 자료를 제거할 때

[학습 자료 홈](README.md)

이 문서는 나중에 제거하기로 결정했을 때 사용하는 안내다. 이번 구조 작성에서 파일·브랜치·프로젝트를 삭제하지 않았다.

## 제거 범위

문서 영역은 저장소 루트의 `learning/` 한 폴더다. 루트 README의 `optional-learning:start`와 `optional-learning:end` 사이 안내 블록도 함께 제거한다. 정식 문서의 과거 변경 이력에 남은 학습 작업 기록은 보존할 수 있다. 과거 기록은 제거 대상 파일에 필수 링크를 두지 않는다.

## 제거 전 확인

1. 제품 동작·공통 API·필수 설정이 학습 자료에만 있다면 정식 docs 또는 구현 코드의 원본으로 먼저 옮긴다.
2. 제품 작업 완료의 유일한 실행 증거가 이 폴더에 있다면 정식 검수 기록/보관소로 옮긴다.
3. 보존할 수업·이미지·완성본이 있다면 해당 참고 커밋/태그와 자료를 보관한다.
4. `node learning/tools/validate.mjs`로 외부 Markdown 필수 링크와 소스/설정/도구의 텍스트 참조를 확인한다. 이 검사는 Unreal 바이너리 에셋 내부 참조를 검사하지 않는다.

학습 설명용 캡처는 이 폴더 안에 둘 수 있다. 게임에서 로드하는 메시·맵·Blueprint·데이터와 빌드 스크립트는 이 폴더에 두지 않는다.

## 제거 후 확인

- 저장소 루트 기준으로 제거할 절대 경로가 정확히 learning 폴더인지 확인한 뒤 제거한다. Source·Content·Config·docs를 포함한 상위 프로젝트 폴더를 대상으로 하지 않는다.
- README의 선택 안내 블록을 제거한다.
- `node tools/check-project.mjs`를 실행해 정식 문서·데이터·코드 포맷 검사를 확인한다.
- 해당 변경에서 필요한 Editor 빌드/실행 확인을 수행한다. 정적 검사 통과를 Unreal 실행 증거로 대신하지 않는다.

학습 검사 스크립트도 learning 폴더 안에 있으므로 함께 제거된다. 정식 CI나 빌드 설정의 학습 전용 단계를 해제할 필요가 없도록 연결하지 않는다.

## 브랜치와 worktree는 별도

문서 폴더를 지워도 참고 브랜치·태그·worktree·실제 개발 브랜치는 삭제되지 않는다. 이들을 정리할 때는 각각의 미커밋 변경·미병합 커밋·보존할 태그와 실행 산출물을 따로 확인한다. 실제 개발자의 작업을 학습 자료 정리 대상으로 묶지 않는다.
