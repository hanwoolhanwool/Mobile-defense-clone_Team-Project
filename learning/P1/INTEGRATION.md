# P1 통합과 다음 단계 진입

**단계별 최신 기준:** [로드맵](../../docs/production/ROADMAP.md#phase-plan) · [계획/구현 차이](../../docs/production/PHASE_ALIGNMENT.md). 새 규칙을 검증한 P0에서 시작한다. 룰렛·신화·강화·스킬 확장과 사냥/미션/통계/불멸/2배속 후보는 로드맵의 TASK 연결에 따라 세분화한다. 후보 범위를 자동 확정하지 않으며, 후속 10배수 보스·즉시 한도 패배·경로·해상도 회귀를 완료 조건에 포함한다.

## 준비할 검수 기록

| 검수 묶음 | 확인할 내용 | 참고용 실행 | 실제 개발 실행 |
|---|---|---|---|
| 출발점 | 각자의 P0 완료 SHA·API·데이터 호환성 | 미실행 | 미실행 |
| 최소 계약 | 새 공통 타입·초기화·실패 반환·에셋 참조 | 미실행 | 미실행 |
| 기능별 중간 통합 | 강화↔전투, 스킬/웨이브↔보상/UI 등 확정한 경계 | 미실행 | 미실행 |
| 회귀 | 이전 전투·경제·보드·입력·네트워크의 영향 범위 | 미실행 | 미실행 |
| 마일스톤 완료 | 정식 보드·QA가 요구하는 플랫폼·기기·실행 조건 | 미실행 | 미실행 |

구체적인 검사 입력·기대값은 범위를 확정하며 작성한다. 기존 규칙을 학습 문서 안에서만 변경하지 않는다.

## 결과와 인계

실행마다 과정, A/B 입력 SHA·통합 SHA·맵/환경·입력·기대값·실제값·증거·수정/재검사 기록을 남긴다. 제품 완료 증거는 [정식 검수 기록](../../docs/production/TEST_RUNS.md)과 [증거 보관 규칙](../../docs/production/EVIDENCE.md)에 연결한다.

참고용과 실제 개발용을 각각 검증한 뒤 각자의 통합 SHA를 다음 단계 출발점으로 사용한다. 다음 단계는 [마일스톤 양식](../templates/MILESTONE.md)과 같은 폴더 구조로 추가한다. 참고본 제작 진척으로 실제 개발 진척을 대신 표시하지 않는다.

## 변경 기획의 필수 회귀

- [ ] 두 그룹의 자기 보드 순환과 중앙 공동 공격·해상도별 입력 정합.
- [ ] 계정/전투 보정 후 현재 수와 최대 수 M의 표시·서버 판정 일치, N ≥ M 즉시 단일 패배.
- [ ] 포함된 10배수 웨이브 보스 출현·제한 시간 전 처치/마감 생존 및 종료 후 중복 처리.
- [ ] UI 재생성/서비스 연결 또는 재접속 때문에 RouteIndex·보스 제한 시각·결과·보상이 초기화/중복되지 않음.
- [ ] 이번에 채택한 확장 기능과 미확정 후보, 실제 수행한 검수 범위 구분.
