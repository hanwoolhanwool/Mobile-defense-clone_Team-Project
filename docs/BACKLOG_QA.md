# 개발 백로그와 QA 기준

기획 체계 0.2 / 모바일 우선 확정. 각 ID는 이슈 추적기에 그대로 옮길 수 있다. P0=핵심 검증, P1=MVP, P2=온라인 출시 준비. 아래 작업량은 **담당자의 집중 작업일 추정**이며 달력 일정이나 총 프로젝트 확정 견적이 아니다. 아트·코드 작업은 인력이 있으면 병행할 수 있다.


[기획 허브](README.md) · [작업 상태·실제 담당자](production/BOARD.md) · [검수 실행 기록](production/TEST_RUNS.md)

이 문서는 작업 정의와 QA 기대 결과의 원본이다. 진행 상태는 작업 보드에서만 관리한다. TASK는 개발 작업, QA는 테스트 시나리오이며 서로 다른 ID다. QA 시나리오가 등록되어 있다는 것은 실행 통과를 뜻하지 않는다.

## 1. 첫 10일 실행 계획

**DEC-021 적용:** [원작 대조 기록](product/ORIGINAL_REFERENCE.md)의 미확인 게임 규칙은 관련 작업 착수 전 원작 버전·모드·실제 입력과 결과를 확인하고 수용 기준을 갱신한다. 아래 기존 수치·이동/잠금/타깃/재료 교환 QA는 초안 검사용이며 원작 재현을 증명하지 않는다. 특히 재료 교환은 원작 근거 확인 전 구현 대상에서 보류한다. 서버 권한·중복 소비 방지와 DEC-019의 P0 검증 규모는 유지한다. 문서·데이터 검사 통과로 이 대조를 대체하지 않는다.

DEC-019에 따라 첫 10일에는 8종·10웨이브·보스 1종의 기본 전투를 검증한다. 공격 훈련·장치 가속, 희귀 4종 고유 스킬과 정식 3웨이브 튜토리얼은 P1로 통일한다. 전설/신화·도전·강화 등 미구현 기능 버튼은 일반 사용자용 P0에서 숨긴다. 희귀→영웅 합성은 기존 P0 비활성 규칙을 유지한다. 완성 아트나 계정 백엔드를 선행 조건으로 삼지 않는다.

10일은 확정 마감일이 아닌 작업 순서·추정이다. 기기 미정(OPEN-008) 동안 독립적인 PC·빌드 작업은 진행하되 Android 실기기 터치 완주 전에는 P0 최종 통과를 보류한다. 5판은 시드·승패·피드백을 남기는 반복 검사이며 전승 조건이 아니다. 기본 공격만 있는 P0에서 고유 스킬의 역할별 밸런스까지 검증했다고 판단하지 않는다.

## 6. 단계별 완료·출시 차단 기준

### P0 핵심 검증 — DEC-019

- 일반 C01~C04·희귀 R01~R04, 기본 적 1종·보스 1종, FinalWave=10 프로파일 적용. 일반/희귀 85/15, 보장 시 희귀 100%, 일반→희귀 합성 및 배치·판매 확인.
- 8종 기본 공격·능력치가 적용되고 희귀 고유 스킬은 발동하지 않음. 강화 레벨은 0이며 직접 강화 요청도 재화·레벨·보드·카운터·RNG 변경 없이 거절.
- 짧은 안내만으로 조작 가능하고 미구현 기능 버튼·고유 스킬 설명이 노출되지 않음. 정식 3웨이브 튜토리얼은 P1 검사로 남김.
- PC 패키징 2인 구성에서 상태 일치와 중복 소비·유닛 손실 0건 확인. 실제 두 프로세스/두 장치 구성, 지연 조건과 로그를 기록.
- 승리·과밀·보스 시간초과·최종 잔여 적의 경계를 P0 최종 웨이브 10에 적용해 검사. QA-TIME-01~07의 해당 조건과 단일 결과 확정·11웨이브 미생성을 확인.
- Android 실기기에서 P0 전투를 터치만으로 10웨이브 완주하고 QA-MOB-01/04·QA-VIS-02/03의 해당 화면·입력 조건과 기존 30FPS 초기 측정을 기록. 기본 템플릿 맵 실행은 완주 증거가 아님.
- 기존 5판 반복의 시드·버전·승패·관찰을 기록. 자연 플레이 완주와 승패 경계 재현은 별도 검사로 수행할 수 있으며 전승을 요구하지 않음.
- PC 검사와 Android 실제 완주가 모두 통과해야 P0 최종 통과. 기기 미정·실행 미완료는 NotRun으로 남기고 완료로 처리하지 않음.

### P1 MVP

- 서버와 클라이언트의 승패 불일치, 자원·유닛 중복 또는 손실 버그 0건.
- 20종·16스킬·4레시피 전부 작동하고 모든 필수 데이터 참조 유효.
- 30웨이브를 승리·패배 모두 정상 완료하며 결과 보상 중복 없음.
- 두 플레이어 연결 조건을 명시한 테스트 통과.
- Android 패키징 빌드에서 모든 핵심 기능의 터치 조작·HUD 판독성·최소 성능 목표를 확인.
- 저품질 모드에서도 적 수·보스 타이머·상태가 읽힘.
- 플레이 테스트의 시드·버전·조건과 알려진 밸런스 문제 기록.

### P2 온라인 공개 준비

- 전용 서버 빌드·서버 배정·친구 코드·계정 인증·버전 거절 동작.
- 60초 재접속·봇 인계·확정 이탈·서버 종료 처리.
- 서버 결과를 계정 서비스에 멱등 지급, 클라이언트 로컬 조작으로 증가 불가.
- 지원 기기와 OS/SDK 조합을 실제 빌드 기준으로 확정.
- 장애 관측, 새 매치 시작 차단, 서버 로그 조회 절차 확인.
- 스토어용 화면·설명·배포 설정과 실제 게임 기능 일치.

동봉 데이터 검사 통과만으로 위 항목을 완료 처리하지 않는다. 각 항목에는 실행 빌드, 기기, 날짜, 증거 로그 또는 영상, 담당자를 기록한다.
