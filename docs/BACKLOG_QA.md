**최신 달력 계획:** [개발 계획서](production/DEVELOPMENT_PLAN.md). DEC-038의 주5일·에셋 사용을 적용한다. 아래 기존 집중 작업일을 새 일정에 다시 더하지 않는다.

**새 착수 기준(2026-09-16):** [촬영본 기반 P0 재기획](design/P0_REPLAN.md)의 G0~G4와 PLAN 검수를 먼저 적용한다. 종전 12칸/치수/경제 수치에 대한 통과는 기존 프로토타입 결과다. DEC-039의 가로 6칸×세로 3칸, 개인 18칸·전체 36칸을 검사하고 원작 조작 근거를 연결한다. 기획용 생성 데이터는 Schema2/Rules0.3.0으로 갱신했으며 기존 실행 결과는 승계하지 않는다.

기획 체계 0.2 / 모바일 우선 확정. 각 ID는 이슈 추적기에 그대로 옮길 수 있다. P0=핵심 검증, P1=MVP, P2=온라인 출시 준비. 아래 작업량은 **담당자의 집중 작업일 추정**이며 달력 일정이나 총 프로젝트 확정 견적이 아니다. 아트·코드 작업은 인력이 있으면 병행할 수 있다.

## 1. 첫 10일 실행 계획

**DEC-021 적용:** [원작 대조 기록](product/ORIGINAL_REFERENCE.md)의 미확인 게임 규칙은 관련 작업 착수 전 원작 버전·모드·실제 입력과 결과를 확인하고 수용 기준을 갱신한다. 아래 기존 수치·이동/잠금/타깃/재료 교환 QA는 초안 검사용이며 원작 재현을 증명하지 않는다. 특히 재료 교환은 원작 근거 확인 전 구현 대상에서 보류한다. 서버 권한·중복 소비 방지와 DEC-019의 P0 검증 규모는 유지한다. 문서·데이터 검사 통과로 이 대조를 대체하지 않는다.

일차는 기존 참고 추정이며 실제 착수는 G0~G4의 통과 순서를 따른다. [단계별 로드맵](production/ROADMAP.md#p0-gates)에서 담당·증거를 확인한다.

### P0 핵심 검증 — DEC-019/033/034

- 일반 C01~C04·희귀 R01~R04·영웅 E01~E04·전설 L01~L04 총16종, 기본 적 1종·보스 1종, FinalWave=10 프로파일 적용. 확인된 소환·합성·배치·판매 동작을 검사한다. 기존 일반/희귀 85/15와 보장 희귀 100%는 실험 프로필이며 원작 확정 수용 기준이 아니다.
- DEC-037의 동일 뭉치 자동 추가·최대 3·초과 시 새 뭉치·선택 UI를 QA-BOARD-11~13으로 검증한다.

- 짧은 안내만으로 조작 가능하고 미구현 기능 버튼·고유 스킬 설명이 노출되지 않음. 정식 3웨이브 튜토리얼은 P1 검사로 남김.
- PC 패키징 2인 구성에서 상태 일치와 중복 소비·유닛 손실 0건 확인. 실제 두 프로세스/두 장치 구성, 지연 조건과 로그를 기록.
