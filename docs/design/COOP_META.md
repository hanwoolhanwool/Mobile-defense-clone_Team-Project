# 협동·접속·성장·저장

[기획 허브](../README.md) · [작업 보드](../production/BOARD.md) · [검수 기준](../BACKLOG_QA.md)

문서 상태와 담당자는 위 메타데이터를 기준으로 한다. 사용자 확정 조건은 결정 기록을 따른다. 나머지 내용은 프로토타입용 설계안이다. 기획 작성 상태와 실제 구현 상태는 별도로 관리한다.

이 파일이 해당 기능의 편집 원본이다. 기존 GDD 장 번호를 유지해 이전 기획과 대응시킨다. 수치·데이터 타입은 허브의 원본 구분표를 따라 함께 변경한다.

## 11. 협동·매칭·이탈 처리

### 11.1 협동 규칙

공용 적 수와 승패를 공유한다. 둔화·방어 약화는 누구의 공격에도 도움이 되고, 지원 오라는 범위 내 상대 수호자에게도 적용된다. 개인 골드·보드·강화 수준은 분리한다. 아군 유닛을 강제로 합성하거나 재화를 사용하지 않는다.

핑은 `보스 집중`, `둔화 필요`, `합성 준비`, `좋아요` 네 가지로 제한한다. 최근 핑을 3초 표시하고 개인당 2초 쿨다운, 큐에 최대 3개만 둔다. 일반 채팅은 포함하지 않는다.

### 11.2 접속 단계

P0/P1에서는 PC 개발 빌드의 리슨 서버 + 로컬 접속으로 검증한다. 호스트 종료 시 세션이 끝나며 호스트 이전은 구현하지 않는다. 연습 모드는 로컬 서버와 보조 봇으로 같은 전투 코드를 사용한다.

P2에서는 친구 방 생성 → 6자리 방 코드 → 코드 입력 → 준비 완료 → 전용 서버 배정 → 전투로 이어진다. 방 코드 만료 10분, 정원 2명, 전투 시작 후에는 원래 참가자의 재접속만 허용한다. 무작위 타인의 중도 입장은 없다. 매칭 SDK만으로 전용 게임 서버 호스팅이 자동으로 해결된다고 가정하지 않는다.

### 11.3 재접속·이탈

전용 서버에서 접속이 끊기면 기존 수호자 공격과 전투 시간은 계속 흐른다. 5초 뒤 해당 자리에 보조 봇을 활성화한다. 60초 동안 원래 계정의 복귀를 허용하고, 복귀하면 현재 보드·재화·보장 카운터·쿨다운의 전체 스냅샷을 전송한 뒤 다음 논리 스텝부터 봇을 끈다.

60초 경과 뒤에는 복귀를 거절하고 그 자리는 결과까지 봇이 맡는다. 이탈자에게는 이탈 확정 시점까지 완료한 웨이브 기준 실패 보상만 지급한다. 남은 참가자는 실제 최종 결과 보상을 받는다. 자발적 나가기는 즉시 이탈 확정으로 처리한다. 둘 다 확정 이탈하면 서버를 종료한다.

### 11.4 보조 봇의 명시적 우선순위

1초마다 한 번 판단하고 명령은 인간과 같은 서버 검증 경로를 이용한다. 우선순위는 빈 칸 없고 합성 가능하면 합성 → 빈 칸 있고 골드가 다음 소환 가격의 2배 이상이면 소환 → 공격 훈련 현재 레벨이 `floor(Wave/5)`보다 작고 비용이 있으면 강화 → 가능한 신화 제작 → 영웅 이상 보장 도전 또는 별조각 4개 이상이면 도전 → 가능한 합성 순이다. 어느 것도 불가능하면 대기한다.

봇은 재료 교환과 판매를 하지 않으며 추적 잠금을 무시하지 않는다. P0에서는 존재하지 않는 행동을 건너뛴다. 결과 화면에 봇이 참여한 시간을 표시하여 플레이 테스트 분석에서 사람 2인 세션과 구분한다.

## 13. 성장·저장·보상

### 13.1 MVP 영구 성장

영구 공격력 강화는 없다. 모든 수호자는 첫 일반 매치부터 소환·합성·제작 가능하다. 도감은 발견 여부만 가리고 잠긴 유닛 때문에 확률 풀이나 레시피가 달라지지 않는다.

계정 레벨은 1~20, 다음 레벨에 필요한 경험치는 `100+50*(현재레벨-1)`이다. 최대 레벨에서는 경험치를 더 쌓지 않는다. 장식 해금은 레벨 2/5/10/15/20에 각각 받침대 색·프로필 프레임·공방 깃발 등 5개를 제공한다. P1에서는 텍스트 해금만 먼저 구현해도 된다.

### 13.2 결과 보상

완료 웨이브 수 W는 제한 시간 종료까지 생존한 웨이브 또는 조기 최종 승리 시 30이다. 일반 매치 경험치=`10*W + (승리면100, 아니면0)`. 보스 시간 초과로 10웨이브에서 실패하면 W=9다. 연습은 경험치 0, 도감 발견만 기록한다.

온라인 중단 Aborted는 결과 보상을 확정하지 않고 재시도 안내를 한다. 정식 서비스에서 별도 보상 정책을 도입하면 운영 규칙으로 관리한다. 클라이언트 로컬 저장을 온라인 보상의 신뢰 근거로 사용하지 않는다.

### 13.3 저장 구조

로컬 프로필은 SaveVersion, ProfileId, Experience, Level, TutorialStep, DiscoveredUnitIds, CosmeticIds, EquippedCosmeticIds, Settings를 갖는다. 진행 중 온라인 매치는 로컬에 저장해 복원하지 않는다. P2 재접속은 살아 있는 서버 상태를 복원한다.

결과 지급 키는 MatchId+AccountId다. P1 로컬에서도 처리 완료 키를 저장해 결과 화면 재진입으로 경험치를 중복 수령하지 않게 한다. P2는 서버의 결과 커밋 및 계정 서비스의 원자적 중복 검사로 대체한다.
