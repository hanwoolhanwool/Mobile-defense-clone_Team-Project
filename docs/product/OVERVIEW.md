# 제품 방향과 범위

[기획 허브](../README.md) · [작업 보드](../production/BOARD.md) · [검수 기준](../BACKLOG_QA.md)

문서 상태와 담당자는 위 메타데이터를 기준으로 한다. 사용자 확정 조건은 결정 기록을 따른다. 나머지 내용은 프로토타입용 설계안이다. 기획 작성 상태와 실제 구현 상태는 별도로 관리한다.

이 파일이 해당 기능의 편집 원본이다. 기존 GDD 장 번호를 유지해 이전 기획과 대응시킨다. 수치·데이터 타입은 허브의 원본 구분표를 따라 함께 변경한다.

## 적용 기준

**DEC-021: 게임 규칙과 조작은 원작의 실제 동작을 확인해 재현한다.** 아래의 자체 수치·편의 기능은 [원작 대조 기록](ORIGINAL_REFERENCE.md)에 따라 재검토하며, 근거가 없는 항목을 원작 규칙으로 구현하지 않는다. UE5·3D·모바일 개발 조건과 DEC-019의 P0 중간 검증 범위는 유지한다.

기존 초안은 **플레이어 2명이 3D 피규어 수호자를 무작위로 소환하고, 합성·배치·강화로 30웨이브를 버티는 게임**이었다. DEC-021 이후 이 수치·규칙은 원작 대조 대상이다. 가칭과 모든 콘텐츠명은 변경 가능하다. 아래 수치는 별도 표시가 없어도 초기 설계값이며, 원작 실측값 또는 밸런스 검증 결과가 아니다.

### 문서 적용 기준

원작 대조 대상은 DEC-022의 Android 2.0.11 · 보통 모드다. 버전은 2026-09-11 공식 스토어 상세 정보에서 확인했으며, 과거 자료의 동작과 해당 버전의 일치 여부는 별도 검증한다.

| 구분 | 기준 |
|---|---|
| 사용자 확정 조건 | `운빨존많겜`의 게임 규칙·조작 재현(DEC-021), 3D 에셋, UE5, 모바일 우선 |
| 모바일 검증 순서 기본안 | Android 실기기 우선 검증, iOS 후속 검증 |

| 모바일 렌더링 | Mobile Forward와 사전 계산 조명 중심의 단순 라이팅(DEC-013). 설정·맵 적용 및 기기 검증 대기 |

| 프로젝트 출발점 | 기존 Mobile_defense_clone 프로젝트·모듈 유지, 모듈 내부 전용 코드와 Content/LD/ 구성(DEC-008) |

| 문서 충돌 처리 | 기능별 명세가 규칙 원본. 데이터 편집·생성 경로는 기획 허브의 원본 표를 따름 |

모바일을 우선 출시 대상으로 확정한다. 화면·조작·아트·성능의 승인 기준은 모바일 실기기로 잡고, Windows PC는 개발 및 네트워크 테스트 환경으로 사용한다. Android 검증 뒤 iOS 빌드 환경과 기기 검증을 별도 작업으로 편성한다. 세로 화면·터치 기준은 DEC-014로 확정했으며, Android→iOS 검증 순서는 기존 작업 기본안으로 유지한다.

모든 전투 기능은 터치만으로 완료할 수 있어야 한다. 마우스 오버 설명은 탭 상세 패널로 대체하고, PC 단축키에만 연결된 기능을 만들지 않는다. 첫 주에 Android 패키징·터치·SafeArea를 확인한 다음 전투 콘텐츠를 늘린다.

## 1. 제품 목표와 원작 참고 범위

### 1.1 한 문장 소개

장난감 공방을 침입한 불량 장난감들로부터 지키기 위해, 두 제작자가 무작위로 나온 수호자 피규어를 합치고 전설 작품을 완성하는 협동 디펜스.

### 1.2 목표하는 재미

| 축 | 플레이어가 느낄 장면 | 구현 수단 |
|---|---|---|
| 기대 | 소환 버튼을 누르기 전의 짧은 긴장 | 등급 확률, 희귀 이상 보장 카운터, 0.35초 결과 연출 |
| 선택 | 당장 딜을 유지할지 상위 등급을 만들지 고민 | 3개 합성, 전설 제작 재료 표시, 보스 예고 |
| 반전 | 밀리던 전장을 상위 유닛 하나가 정리 | 광역 전설·신화 스킬, 획득 알림, 처치 수 피드백 |
| 협동 | 아군 둔화 위에 내 광역 공격이 겹침 | 공용 적 경로, 팀 상태이상, 도움 핑 |
| 수집 | 작은 피규어가 점점 특별해짐 | 실루엣, 움직임, 받침대, 도감 회전 보기 |

순간 조작 능력보다 확률 결과에 적응하는 판단을 중시한다. 수호자는 자동 공격하며, 플레이어가 직접 캐릭터를 이동 조종하거나 공격 키를 누르지 않는다.

### 1.3 원작 재현과 기존 초안의 구분

공식 스토어는 원작의 무작위 유닛 소환, 합성, 룰렛형 도전을 핵심 기능으로 소개한다. Google Play의 소개 기사에서는 협동 상황과 유닛의 확률적 변화를 설명한다. 본 기획은 이 핵심 루프를 출발점으로 사용한다. [원작 공식 스토어](https://play.google.com/store/apps/details?hl=ko&id=com.percent.aos.luckydefense), [Google Play 소개](https://play.google.com/store/apps/editorial?gl=KR&id=mc_editorialmd_launchnontp_lucky_defense_fcp)

다음 표는 원작 대조 전 작성한 프로젝트 초안이다. 공식 소개가 이 표의 확률·보장·재료 수·웨이브 수를 입증하지 않는다. DEC-021 이후에는 원작과 확인된 차이를 기능 명세·데이터·QA에 함께 반영한다.

| 참고할 구조 | 기존 프로젝트 초안(원작 대조 대기) |
|---|---|
| 무작위 소환 | 골드 소환 + 실패 보정이 있는 별조각 도전 |
| 동일 유닛 합성 | 동일 UnitId 3개 → 상위 등급에서 균등 추첨 |
| 협동 방어 | 한 개의 공용 순환 경로와 두 개의 배치 보드 |
| 강한 유닛 완성 | 재료 3종을 소비하는 신화 제작 |
| 짧은 반복 플레이 | 30웨이브 약 15분, 전투 자원은 매판 초기화 |

3D 전환은 자유 카메라나 지형 고저차를 추가하는 방식으로 확장하지 않는다. 전투 판정은 XY 평면에 두고, 피규어의 체적·애니메이션·소환 연출이 3D의 장점을 보여준다. 캐릭터명, 외형, 사운드, 텍스트, 맵 장식, UI 그래픽은 공방 테마로 새로 제작한다.

## 2. 범위와 단계별 완성 기준

### 2.1 P0: 핵심 검증 빌드

DEC-019로 아래 범위를 확정했다. 소환·합성·배치의 기본 전투 루프를 먼저 검증하며, 강화와 희귀 고유 스킬의 재미·밸런스는 P1에서 검증한다.

| 항목 | 수량·범위 |
|---|---|
| 맵 | 회색 박스 공방 1개, 공용 순환 경로 1개 |
| 수호자 | 일반 C01~C04 + 희귀 R01~R04, 총 8종. 기본 공격·능력치 차이만 적용, 고유 스킬 비활성. 외형은 임시 에셋 허용 |
| 적 | 기본 적 1종, 10웨이브 보스 1종 |
| 룰 | 10웨이브, 골드 소환, 일반→희귀 합성, 배치·판매, 공용 적 수 패배 |
| 협동 | 개발 PC 리슨 서버와 클라이언트 1대, 로컬 접속 |
| UI | HUD, 선택 패널, 소환 버튼, 결과 화면과 짧은 조작 안내. 미구현 기능 버튼 숨김 |
| 제외 | 공격 훈련·장치 가속, 희귀 고유 스킬, 정식 3웨이브 튜토리얼, 별조각 도전·신화·계정 성장·인터넷 매칭·상점 |
| 완료 조건 | PC 2인 상태 일치·중복 소비 방지·승패 경계 검사와 Android 실기기에서 P0 전투의 터치 완주 모두 통과 |

P0 데이터는 전용 프로파일을 사용한다. 일반/희귀 소환 비중은 85/15이며 희귀 이상 보장 시 희귀 100%다. 희귀 합성 버튼은 이 빌드에서 비활성화한다. 최종 기획의 영웅이 나와 화면이 깨지는 일을 방지한다.

P0는 강화 레벨을 0으로 유지하고 강화 구매를 서버에서 거절한다. 희귀 SkillId가 전체 데이터에 존재해도 P0에서는 발동·효과·스킬 설명을 활성화하지 않는다. P1용 데이터의 삭제나 능력치 재조정은 이번 범위 결정에 포함하지 않는다. 희귀 합성은 기존 비활성 규칙을 유지하고, 새로 제외한 기능의 버튼은 노출하지 않는다.

첫 Android 검증 기기는 미정(OPEN-008)이다. 기기 선정·실제 터치 완주 전에는 P0 최종 통과를 보류하되 독립적인 문서·PC·빌드 작업은 진행할 수 있다. 상세 판정과 실행 증거는 [백로그·QA](../BACKLOG_QA.md) 및 [로드맵](../production/ROADMAP.md)에 연결한다.

### 2.2 P1: 제작 가능한 최소 완성 게임

30웨이브, 20종 수호자, 4종 일반 적, 3종 보스, 모든 전투 룰, 2인 네트워크, 튜토리얼, 결과·도감·로컬 저장, 기본 3D 아트 및 성능 측정을 갖춘다. P0에서 제외한 공격 훈련·장치 가속, 희귀 4종 고유 스킬과 정식 3웨이브 튜토리얼도 포함한다. 이것이 문서에서 말하는 **MVP**다. 인터넷 공개 운영과 유료 상점은 별도 단계다.

### 2.3 P2: 온라인 출시 준비

전용 서버, 계정 인증, 인터넷 방 코드, 재접속, 보상 중복 방지, 서버 검증 저장, Android 실기기 QA, 서비스 모니터링을 추가한다. 이후 iOS를 검증한다. 공개 매칭은 인구가 충분할 때 추가하며, 최초에는 친구 방을 우선한다.

### 2.4 이번 범위 밖

PvP, 길드, 채팅, 시즌 패스, 유료 확률형 상품, 장비 옵션 파밍, 오픈월드, 물리 기반 유닛 이동, 자유 카메라, 수호자 수동 궁극기, 보스별 별도 스테이지는 포함하지 않는다. 첫 출시 이후 별도 기획으로 평가한다.

## 3. 플레이 경험과 게임 흐름

아래는 P1 이후의 목표 경험이다. P0에는 2.1절의 허용 기능만 적용하며 강화·고유 스킬·정식 로비/튜토리얼 구현을 P0 완료 조건에 추가하지 않는다.

### 3.1 1판 루프

```text
로비 → 연습/친구 방 선택 → 로딩·준비 → 10초 준비
 → 골드 소환 → 자동 공격 → 골드 획득
 → 배치 / 합성 / 강화 / 별조각 도전 / 신화 제작
 → 10·20·30웨이브 보스 → 승리 또는 패배 → 결과 → 다시 하기
```

### 3.2 시간대별 의도

| 시간 | 목표 행동 | 화면 피드백 |
|---|---|---|
| 준비 10초 | 시작 골드로 5회 소환, 공격 가능한 배치 | 추천 칸 표시, 다음 소환 가격 |
| 0~3분 | 첫 합성, 전투 강화 1단계 | 같은 유닛 3개 강조, 합성 결과 |
| 3~5분 | 첫 보스에 맞춰 딜 유지 또는 합성 | 보스 1웨이브 전 예고 |
| 5~10분 | 역할 분담, 별조각 도전, 전설 확보 | 아군 둔화/방어 약화 보유 아이콘 |
| 10~15분 | 신화 제작, 최종 보스 대비 | 재료 추적, 보스 체력, 위험 경고 |
| 결과 | 실패 이유 이해, 다음 판 시도 | 마지막 웨이브, 패배 원인, 내가 만든 최고 등급 |

이는 목표 경험이다. 첫 전설·신화 획득 시점은 실제 테스트에서 측정하며, 초기 데이터만으로 달성됐다고 판단하지 않는다.

### 3.3 반복 플레이 동기

전투 중의 선택 변화와 도감 발견을 우선한다. 영구 전투력 차이를 두지 않아 친구와 바로 합류할 수 있게 한다. 전투에서 유닛·조합식을 처음 사용하면 도감이 밝혀지고, 계정 레벨은 장식과 연습 안내를 해금한다.
