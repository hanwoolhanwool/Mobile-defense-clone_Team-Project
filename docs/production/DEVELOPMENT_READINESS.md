# 개발 전 문서 검토 종합

[기획 허브](../README.md) · [작업 보드](BOARD.md) · [결정 기록](../DECISIONS.md) · [검수 기록](TEST_RUNS.md)

2026-09-14 기존 실행 기록을 반영한 문서 검토 결과다. **Windows 기본 준비 이후 Android 도구·패키징 준비로 진행할 수 있으나, 원작 게임 규칙 전체가 구현 기준으로 확정된 상태는 아니다.** Windows 실행 근거는 RUN-20260913-02/03이며 이번 문서 검토를 새 빌드·구현 완료로 표시하지 않는다. 상세 규칙·OPEN 항목·작업 상태는 연결된 원본에서 관리한다.

## 1. 검토한 6개 항목

| 항목 | 이번 검토에서 정리한 내용 | 남아 있는 검증 |
|---|---|---|
| 1. 개발 환경·빌드 | 기존 프로젝트 유지, Windows 도구 적용·기본 빌드/실행 증거, PC/Android 명령·산출물·로그 기준 | Android 목표 도구 적용·패키징·실기기, 한국어 엔진 진단 문제 재확인. 새 환경은 다시 검증 |
| 2. P0 범위 | 8종·10웨이브 기본 공격, 강화·고유 스킬·정식 튜토리얼은 P1, PC 2인+Android 터치 완료 조건 | 실제 동작·승패 경계·기기 실행. P0 규모 합의가 기존 자체 확률·경제 수치를 원작값으로 확정하지 않음 |
| 3. 명령 계약 | 서버 권한, 명령별 payload, 중복 소비 방지, 재시도·늦은 응답 | 실제 네트워크 검수. Single/Lock/Target/Swap 기능 존재는 원작 확인 후 명령·UI·QA를 함께 조정 |
| 4. 원작 대조 | Android 2.0.11 보통 모드 기준, 공개 화면·영상 관찰 OBS-01~09 | 기준 버전의 실제 입력·결과 일치 및 이동·분산 합성·판매 조건. 전체 대조 완료 아님 |
| 5. 화상 종료 | 기존 초안의 마지막 예약 틱·만료·재적용·사망·마감 순서 | P1 런타임 QA. 화상 자체 수치·중첩 방식의 원작 확인은 별도 |
| 6. 개발 도구 | 저장/적용 복구, 실행 입출력·취소·결과 계약, P1 작업 4개·QA 8개 연결 | 도구 구현·원본 이관·UE 임포트 복구·실제 회귀 실행. P0의 추가 필수 조건 아님 |

## 2. 해당 작업을 시작하기 전에 해결할 항목

미정 항목을 프로젝트 전체의 중단 사유로 묶지 않는다. 아래 각 조건은 영향을 받는 작업에 적용한다.

| 우선 | 조건·현재 상태 | 영향을 받는 작업 | 다음 행동·조건 충족 증거 |
|---|---|---|---|
| 빌드마다 | 기존 입력 보존은 TASK-CORE-01에서 확인. 새 실행은 기준 커밋·로컬 변경·입력 해시를 새로 기록 | 실제로 빌드하는 작업 | Git 제외 로컬 설정을 포함한 실제 입력을 식별하고 별도 작업 폴더에서 실행 |
| 먼저 | OPEN-001: 담당자·가용 시간 미정 | 실제로 착수할 작업 | 착수 작업의 담당자·범위를 보드에 기록. 기존 일정은 추정이며 팀 전체 채용·배정 완료를 기다릴 조건은 아님 |
| 환경 작업 안에서 | OPEN-002: Windows 기본 검증 완료, Android 적용·빌드는 미검증 | [TASK-MOB-01](../BACKLOG_QA.md#TASK-MOB-01) | Android 설치·경로·버전 확인 후 문서 순서로 빌드. PC·Android 빌드 모두 Pass인 로그로만 엔진 후보를 고정 |
| 보드 구현 전 | OPEN-009: 기존 4×3·24칸과 공개 화면 6×3 관찰이 불일치, 기준 버전의 좌표·이동 동작 미확인 | [TASK-MAP-01](../BACKLOG_QA.md#TASK-MAP-01), [TASK-BOARD-01](../BACKLOG_QA.md#TASK-BOARD-01), TASK-UI-01 | 버전·모드·입력 전후 배치를 확인하고 보드 차원·CellId·배치/교환·합성 결과 칸을 명세·QA에 반영. 기존 24칸을 원작 합격 기준으로 사용하지 않음 |
| 경제 규칙 구현 전 | OPEN-009: 비용 상한 60·전 등급 골드 판매 가정은 관찰과 불일치, 계정/유물별 수치 미확인 | [TASK-ECON-01](../BACKLOG_QA.md#TASK-ECON-01), [TASK-DATA-01](../BACKLOG_QA.md#TASK-DATA-01), TASK-UI-01 | 소환·판매의 재화 종류·수량·보장 조건을 확인. 기능 명세·생성기·JSON·구조체·HUD·QA를 같은 근거로 갱신하고 원작 확인 범위 기록 |

원작 근거가 필요한 범위와 독립적인 프로젝트 점검, 빌드 경로, 서버 권한·중복 요청 처리 구조의 검토는 진행할 수 있다. 미확인 자체 수치로 시험한 결과에는 초안 기술 검증임을 표시한다. 2.0.11 이후 버전으로 대조 대상을 자동 변경하지 않는다.

## 3. 개발 중 정해진 시점에 확인할 항목

| 확인 시점 | 항목 | 연결 작업·완료 증거 |
|---|---|---|
| 첫 Android 설치 전 | OPEN-008: 실제 기기 모델·OS·GPU·메모리·지원 ABI 확인 | TASK-MOB-01. APK 설치·실행과 기기 정보를 같은 Run에 기록. 기기 미정은 PC/Android 패키징 준비의 중단 사유가 아님 |
| P0 통과 전 | PC 패키징 2인 상태 일치·중복 소비 방지·승패 경계, Android 10웨이브 터치 완주 | [TASK-TEST-01](../BACKLOG_QA.md#TASK-TEST-01), TASK-MOB-01. 기본 맵 실행·정적 검사로 대체하지 않음. 5판은 시드·승패 기록이며 전승 조건 아님 |
| 아트 제작 전 | OPEN-004: 공용 리그·에셋 확보·제작 범위 | [TASK-ART-01](../BACKLOG_QA.md#TASK-ART-01). 카메라 기준 판독성·실제 사용할 에셋 및 공수 확인. 완성 아트는 초기 환경 점검의 선행 조건 아님 |
| P1 저장·복귀 기능 구현 전 | 저장 형식 변경, 손상/중단 저장 복구, 보상 지급과 처리 키 저장의 일관성, 앱 백그라운드·복귀 처리의 세부 계약 | [TASK-SAVE-01](../BACKLOG_QA.md#TASK-SAVE-01), TASK-UX-01, TASK-MOB-01. 기존 QA는 있으나 저장 쓰기 중단·버전 이관·P1 로컬 세션 복귀의 상세 설계 추가 검토 필요 |
| P1 스킬·콘텐츠 구현 전 | 원작 스킬·능력치·해금/성장 규칙 확인, 자체 화상 초안과의 차이 | TASK-DATA-02, TASK-COMBAT-02, TASK-ECON-02. 원작 확인과 실제 전투 QA 각각의 증거 확보 |
| 도구 편집 기능 구현 전 | 원본 데이터의 최종 형식·위치와 UE 인터페이스 확인 | [TASK-TOOLS-01](../BACKLOG_QA.md#TASK-TOOLS-01). 이관 전후 값 비교, 저장 충돌·부분 임포트 복구 검수. 현재 생성 JSON은 편집 원본 아님 |
| 지원 성능 확정 전 | OPEN-003: 최소 지원 기기와 성능 기준 | [TASK-PERF-01](../BACKLOG_QA.md#TASK-PERF-01). 첫 기기 선정과 제품 지원 범위를 구분하고 장시간 실제 측정으로 판정 |
| P2/iOS/출시 범위 편성 전 | OPEN-005/006/007: 인터넷 서비스·운영/수익화·iOS 일정 | P2 서버·계정·재접속 작업과 별도 iOS 계획. 현재 Windows/Android P0 착수의 선행 조건 아님 |

이 표는 후속 검토 시점을 연결한 것이며 미정 항목을 새 게임 규칙으로 확정하거나 실제 QA를 통과 처리하지 않는다. 저장·복귀의 추가 검토는 [협동·저장 명세](../design/COOP_META.md)를 원본으로 삼는다.

## 4. 다음 실행 순서

1. TASK-CORE-01의 현재 입력·프로젝트 구조·설치 환경을 확인하고, 첫 개발 작업의 담당자·범위를 기록한다.
2. 확정한 도구·설정 기준과 현재 상태의 차이를 적용하고 Development Editor·PC 기본 빌드의 실행 증거를 확보한다. Android 도구·패키징 검증을 이어서 수행한다.
3. 게임 규칙 작업은 OPEN-009의 보드·이동/합성·판매/소환을 묶어 대조하고 해당 계약을 정리한 범위부터 구현한다. 이 확인은 환경 점검과 독립적으로 진행할 수 있다.
4. 검증된 규칙으로 P0를 통합하고 PC 2인·Android 실기기 검수 후 P1 범위와 일정을 재산정한다. P1 도구 확장 공수는 별도로 산정한다.

이번 종합은 문서 검토 결과만 반영했다. 설치·설정 적용·빌드·게임 구현·커밋·푸시를 실행하지 않았으며 보드의 작업 37개는 기존 상태를 유지한다. 진행 상황은 이 요약을 복제해 갱신하지 않고 작업 보드·검수 기록·원작 대조 원본을 갱신한다.
