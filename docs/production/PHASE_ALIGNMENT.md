# 변경 기획의 개발 단계 반영 점검

**현행 규칙:** [P0 재기획](../design/P0_REPLAN.md)의 DEC-043~047을 따른다. P0 16종·100/20·보스2/60초, P1 80웨이브·사냥/미션/던전·보물/유물/펫 실제 시스템. 고유 콘텐츠는 컨셉 후 결정하며 기존 날짜/공수는 재산정 대상이다.

[로드맵·단계별 기준](ROADMAP.md) · [P0 재기획](../design/P0_REPLAN.md) · [작업 정의](../BACKLOG_QA.md) · [검수 기록](TEST_RUNS.md)

점검일: 2026-09-16. 대상: DEC-032/033/034, 제품 범위·로드맵·작업 보드·첫 실행 계획·A/B 설계와 P0/P1/P2 학습 경로. 이번 판정은 **계획 반영 여부**이며 게임 구현 완료 판정과 구분한다.

**후속 결정:** 점검 이후 사용자 요청(DEC-035)으로 기존 P0 구현·브랜치·학습 자료를 삭제했다. 아래 런타임 차이는 삭제 전 관찰 이력이며 현재 파일 상태가 아니다. [현재 출발점](P0_RESET.md).

## 점검 결론

점검 전에는 부분 반영 상태였다. 전투 명세와 재기획·통합 체크에는 최신 요구가 있었지만 상위 단계 문서와 일부 개별 수업은 이전 내용을 유지했다. 이번에 다음 누락과 충돌을 정리했다.

| 발견한 차이 | 반영한 위치·처리 |
|---|---|
| P0 제품 표의 공용 경로 1개 | 같은 방향의 중앙 구간을 공유하고 각자 보드로 복귀하는 두 폐곡선으로 수정 |
| 첫 실행 계획의 24칸·단일 Spline 및 구도 검수 누락 | G0 공통 계약 → G1 3D 전장/두 바퀴/전 셀 입력 → G2 기능 → G3 PC → G4 Android로 연결 |
| 로드맵의 예전 과밀·정기 보스·HUD 완료 기준 | P0에 N ≥ M 즉시 패배·10웨이브 보스·시간초과·현재/최대 수와 남은 시간·단일 결과 검수 명시 |
| 2.4:1/1:1 또는 12칸을 새 완료 기준처럼 읽을 수 있는 안내 | 치수·비율은 조정 가능, 확정 Rows×Columns 전수 입력 검사로 통일. 과거 캡처/실행 기록의 수치는 보존 |
| P1의 교환 2회·보장 5회 등 미확인 자체 규칙을 완료 조건에 고정 | DEC-045 룰렛/강화 시험표 적용, 보장·교환은 없음. 제작은 컨셉 대기 |
| 사냥·미션·통계 등 촬영 기능의 작업 연결 누락 | P1 확장 후보별 상위 TASK 연결. 후보 추가가 작업 완료나 전체 범위 확정을 뜻하지 않도록 명시 |
| P2 후보와 제품의 채팅 제외 문구 충돌 | 채팅/이모티콘·계정 성장·정식 매칭은 서비스 범위 확정 전 후보. 개발 진입용 로비/고정 프로필과 구분 |
| 역할별 수업·참고 수업에 이전 규칙이 남음 | 단계별 변경 과제와 새 검수 연결. 기존 SHA·캡처·실행 결과를 새 기획 통과로 재표기하지 않음 |

## 단계별 반영 결과

상세 TASK와 확장 후보는 [로드맵](ROADMAP.md)에 연결했다. P0 승인 범위를 새 화면 전체로 확대하지 않았고 기존 37개 작업의 단계·상태·실제 담당자는 그대로다.

## 삭제 전 참고 구현의 차이 — 점검 당시 이력

당시 확인 대상은 로컬 `Mobile_defense_reference_p0` 작업 폴더였으며 이후 삭제됐다. 미커밋 변경이 포함된 현재 파일 관찰이며 과거 SHA의 내용으로 단정하지 않는다. 다른 학습 브랜치에 참고 코드가 이미 있다고 표시하지 않는다.

| 위치 | 확인한 현재 상태 | 후속 P0 작업 |
|---|---|---|
| `data/GameRules.json` / `Defeat` | ActiveEnemyThreshold=100, ContinuousSeconds=3 | TASK-DATA-01: 최대 수 출처 확정, 유예 폐기와 생성기·로더·데이터 일괄 이관 |
| `Source/Mobile_defense_clone/Data/LDGameRules.cpp` | ContinuousSeconds 허용 최솟값 0.05 | 0으로 JSON만 바꾸면 로더와 충돌. 새 즉시 판정 계약으로 함께 수정 |
| `Source/Mobile_defense_clone/Core/LDGameMode.cpp` | 사망 정리 뒤 OvercrowdedSince의 경과 시간을 검사 | TASK-WAVE-01: 수 증가 확정 순간의 N ≥ M 즉시 단일 패배와 결과 이후 중단 |
| `Source/Mobile_defense_clone/UI/LDCombatStatusWidget.cpp` | Enemies에 현재 수만 표시, WaveEndTime 기반 남은 시간 | TASK-UI-01/TASK-NET-01: 현재/최대 수 및 명시적 보스 마감의 복제·표시 계약 적용 |
| 기존 참고 수업·검수 결과 | 이전 프로토타입의 치수·유예·테스트 통과를 설명 | 새 규칙을 적용한 뒤 별도 실행 증거로 재검수. 과거 기록은 보존 |

따라서 **단계별 계획 반영과 참고 코드의 실제 반영은 서로 다른 상태**다. 이번 점검에서 게임 코드를 변경하거나 UE를 실행하지 않았다. 경로 등 나머지 기능도 이 표에 없다는 이유로 새 기획의 실행 검수를 통과한 것으로 간주하지 않는다.

## 남은 확인과 실행

- 컨셉·독자 스킬·신화 제작 재료와 성장 방식.
- P1 던전/사냥 단계 수치와 보물·유물·펫 콘텐츠/획득/비용/중복 표.
- 유닛/적 시험 수치의 실제 밸런스와 Android 기기·터치 완주.
- P0 16종·P1 80웨이브/메타 확장에 따른 일정 재산정, P2 서비스 상세.

상한100/20·보스2/60초·경제/판매/배치/이동 경계는 DEC-043~046으로 확정했다. 이 항목을 다시 미확인 착수 조건으로 두지 않는다. 실행하지 않은 검수는 NotRun으로 유지한다.
