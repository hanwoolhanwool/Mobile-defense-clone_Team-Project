# 게임 개발 에디터 기능 설계

[기획 허브](../README.md) · [자동화 기능 설계](AUTOMATION.md) · [게임 구현 구조](ARCHITECTURE.md) · [데이터 명세](../DATA_SCHEMA.md)

## 1. 목적과 적용 기준

개발자가 게임 데이터를 편집하고, 원하는 전투 상황을 즉시 실행하고, 변경 전후 결과를 비교하는 UE 내부 개발 도구를 만든다. 첫 목표는 **전투 테스트 콘솔 + 웨이브·유닛 편집 + 검증 결과 확인**이다.

이 문서는 사용자의 에디터·자동화 기능 문서화 요청에 따른 확장 설계 초안이다. 현재 게임 기획의 완성 범위인 2인 협동, 30웨이브, 수호자 20종, 소환·합성·신화 제작을 기준으로 작성했다. 해당 기능의 구현 완료나 완성 빌드 실행을 확인했다는 의미는 아니다. 게임 규칙의 원본은 기존 기능 명세이며, 이 문서에 적힌 수치는 도구 사용 사례다.

주 사용자는 기획·밸런스 담당, 게임플레이 개발자, QA, 아트 담당이다. 플레이어에게 제공하는 맵 제작기나 일반 매치의 자동 플레이 기능은 이번 범위에 포함하지 않는다.

## 2. 기능 목록과 우선순위

DEC-019의 P0는 8종·10웨이브·기본 공격 검증 범위다. 도구의 전체 편집 UI와 스킬·스냅샷 지원을 P0 완료 조건에 추가하지 않는다. DEC-021/DEC-022에 따라 아래 4×3 보드·30웨이브·교환·잠금·판매금 등의 사례는 기존 자체 설계이며 [원작 대조](../product/ORIGINAL_REFERENCE.md) 전 확정값으로 사용하지 않는다. 편집 화면은 선택한 데이터 프로파일의 지원 기능과 원작 확인 상태를 표시한다. 미확인 규칙을 시험할 때는 초안 실험으로 기록하며 원작 재현 통과로 집계하지 않는다.

| ID | 기능 | 주요 사용 사례 | 우선순위 | 선행 조건 |
|---|---|---|---|---|
| ED-F01 | 전투 테스트 콘솔 | 보스 직전 상태에서 시작하고 한 스텝씩 판정 확인 | 최우선 | 전투 세션 생성·상태 조회·테스트 초기화 인터페이스 |
| ED-F02 | 웨이브 에디터 | 적 구성·수량·등장 시각·HP·보상을 수정하고 비교 | 최우선 | 웨이브 데이터 로드·검증·임포트 |
| ED-F03 | 유닛·스킬 에디터 | 스탯과 상태이상을 수정하고 시험장에서 측정 | 높음 | 유닛·스킬 데이터 및 실제 전투 계산 |
| ED-F04 | 소환·경제·제작 에디터 | 확률·보장·가격·강화 비용·레시피 편집 | 높음 | 경제 규칙과 확률 시뮬레이션 |
| ED-F05 | 보드·경로 편집 및 분석 | 사거리·오라·경로와 양쪽 보드 차이 확인 | 중간 | 보드·경로 데이터와 좌표 변환 |
| ED-F06 | 유닛 외형 연결 도구 | 메시·애니메이션·아이콘·VFX 연결 및 미리보기 | 중간 | VisualId와 시각 DataAsset 매핑 |

우선순위는 도구 내부의 구현 순서다. 기존 게임 마일스톤 P0/P1/P2나 작업 보드의 진행 상태를 대체하지 않는다.

## 3. 첫 화면과 작업 흐름

UE에 `공방 개발 도구` 창을 추가한다. 첫 버전은 네 탭으로 구성한다.

| 영역 | 표시·조작 | 완료 시 피드백 |
|---|---|---|
| 공통 상단 | 현재 프로젝트·데이터 버전·미저장 변경·대상 테스트 세션 | 편집본과 현재 실행 세션의 데이터 버전을 구분 |
| 테스트 실행 | 시작 웨이브, 프리셋, 시드, 두 플레이어의 보드·재화, 실행·중지 | 초기화 결과와 실행 ID 표시 |
| 웨이브 | 목록, 웨이브 상세, 생성량·HP·보상 그래프 | 변경 전후 값과 오류 위치 표시 |
| 유닛 | 유닛 목록, 스탯·스킬 상세, 시험장 실행 | 실제 측정값과 측정 조건 표시 |
| 검증 결과 | 검증 항목, 실행 상태, 실패 원인, 로그, 이전 실행 비교 | 실패 항목에서 관련 데이터 행으로 이동 |

경제·제작, 보드·경로, 외형 탭은 후속 단계에서 추가한다. 버튼 하나가 저장·임포트·검증·실행을 묶어 처리할 수는 있지만, 각 단계의 성공 여부와 실패 위치는 따로 표시한다.

기본 흐름은 다음과 같다.

```text
데이터 또는 테스트 프리셋 선택
 → 값 편집
 → 변경 전후 차이 확인
 → 원본 저장·검증
 → 생성·UE 임포트·에셋 검증
 → 새 테스트 세션 실행
 → 결과 확인·이전 실행과 비교
```

필수 참조 누락·지원하지 않는 데이터 타입 등 실행 불가능한 오류가 있으면 적용을 중단하고 해당 행과 필드를 표시한다. 작업 중 게임 규칙 버전이 달라지면 기존 테스트 세션에 섞어 적용하지 않고 새 세션을 시작한다.

## 4. 데이터 편집과 저장 원칙

### 4.1 현재 구조와 이관 제안

현재 수치·생성 공식의 편집 원본은 [build-design-data.mjs](../../tools/build-design-data.mjs)이고, `data/DT_*.json` 및 `data/GameRules.json`은 생성 결과다. UE DataTable의 수동 수정도 원본으로 취급하지 않는다. 자세한 현재 계약은 [데이터 안내](../../data/README.md)를 따른다.

에디터 도입 시 편집할 수치와 생성 설정을 별도의 원본 데이터로 분리하는 방안을 제안한다. 예를 들어 `data/source/`에 원본을 두고 기존 생성기는 변환·내보내기를 담당하게 한다. 이 경로는 제안이며 이번 문서 작성으로 원본을 이관하지 않는다.

원본 이관 시 기존 생성 결과와 새 생성 결과를 비교하여 의도하지 않은 밸런스 변경이 없는지 확인한다. 원본 위치가 확정되면 데이터 안내·데이터 명세·검증기와 이 문서를 함께 갱신한다.

### 4.2 편집·적용 규칙

- 편집은 메모리상의 초안에서 시작하며 `저장` 전에는 원본 파일을 변경하지 않는다.
- 저장 전 파일 변경 여부를 확인하고, 다른 사람이 수정한 원본을 덮어쓰는 대신 충돌 내용을 표시한다.
- 실행 취소·다시 실행, 원본으로 되돌리기, 적용 전 변경 비교를 제공한다.
- 저장 전 검증을 통과한 원본에서 생성물을 만들고, 성공한 임포트 결과를 재조회한다. JSON과 실제 로드 데이터의 의미상 값·참조가 일치하는지 확인한다.
- 원본 저장·생성·임포트는 여러 파일과 에셋에 걸친 작업이다. 중간 실패 시 단계를 실패로 표시하고 이전 적용본으로 복구하거나 재시도할 수 있게 한다. 일부만 반영된 상태에서 테스트 실행을 허용하지 않는다.
- 밸런스 버전과 데이터 해시를 결과에 남긴다. 버전 변경 정책은 [관리 방식](../WORKFLOW.md)을 따른다.
- 에셋 임포트 실패가 원본 저장 성공을 숨기지 않도록 `원본 저장됨 / 적용 실패`처럼 상태를 구분한다.

현재 [데이터 검증기](../../tools/validate-design-data.mjs)의 유닛 20종·30웨이브·특정 가격 공식 검사는 특정 초기 밸런스의 기대값이다. 형식·참조·값 범위 검사와 버전별 기대값 검사를 분리하여, 의도한 수치 편집이 모두 데이터 오류로 처리되지 않게 한다.

### 4.3 저장·적용 요청과 실패 복구 계약

아래는 구현할 내부 계약이다. 현재 존재하는 API나 실행 가능한 명령이 아니다. 원본 이관 전에는 생성 JSON·DataTable을 편집 원본처럼 저장하는 버튼을 제공하지 않는다.

| 구분 | 필수 입력·출력 |
|---|---|
| 편집 요청 | OperationId, SourceRevision(열 때 읽은 원본 묶음 해시), 대상 프로파일, 수정 대상 파일/행/필드와 변경 전후 값 |
| 적용 요청 | OperationId, 저장된 SourceRevision, 생성기 버전, 대상 프로젝트·에셋 목록, 이전 AppliedDataHash(첫 적용은 없음). 메모리 미저장 초안은 적용 입력으로 사용하지 않음 |
| 결과 | OperationId, 원본 저장 상태, 적용 상태, 현재 SourceRevision·AppliedDataHash, 단계별 오류 코드·파일/행/필드·로그, 복구 상태 |
| 복구 기록 | 변경 대상 목록, 단계별 완료 여부, 변경 전 파일·에셋 백업 참조와 해시, 생성/임포트 임시 경로. 재시작 후에도 읽을 수 있게 저장 |

동일 프로젝트의 저장·적용은 한 번에 하나만 수행한다. 두 요청을 받으면 뒤 요청은 Busy로 거절하며, 저장 직전 SourceRevision을 다시 비교해 외부 편집을 감지한다. 같은 OperationId·같은 내용의 재요청은 기존 진행/결과를 반환하고 중복 저장·임포트하지 않는다. 같은 ID의 다른 내용은 충돌로 거절한다.

| 단계 | 성공 시 | 실패·취소 시 |
|---|---|---|
| 초안 검사·원본 저장 | 참조·형식 검사 후 변경 묶음 저장, 새 SourceRevision 기록 | 저장 전 오류는 원본 불변. 다중 파일 저장 중 실패하면 변경 전 원본 복구·해시 확인, 불완전하면 RecoveryRequired |
| 생성·검증 | 임시 경로에 생성하고 데이터 검증, 생성물 목록·해시 확정 | 저장된 원본은 유지하고 `원본 저장됨 / 적용 실패` 표시. 기존 적용본을 실행 기준으로 유지 |
| 임포트·로드 비교 | 대상 에셋 백업 후 임포트, 실제 로드 값·참조와 생성값 비교 | 일부 임포트 실패 시 이번 작업 대상 에셋·생성물 복구 후 재로드·해시 검증. 원본은 자동으로 과거 버전으로 되돌리지 않음 |
| 적용 확정 | 모든 비교 성공 후 AppliedDataHash 갱신, 새 테스트 세션 허용 | 복구 검증 실패 시 RecoveryRequired로 새 테스트 실행·추가 적용 차단. 로그·백업 보존 후 명시적 복구 필요 |

원본 묶음과 UE 에셋 묶음이 하나의 파일처럼 원자적으로 저장된다고 가정하지 않는다. 첫 적용 실패로 이전 적용본이 없는 경우에도 실행을 차단한다. 기존 세션에 새 데이터를 실시간으로 섞지 않으며, 적용 전 해당 테스트 세션을 종료한다. 복구 성공 후에는 마지막 정상 적용본으로 새 세션을 만들 수 있으나 현재 저장 원본과 다르면 그 차이를 표시한다.

취소는 단계 경계에서 확인한다. 파일·에셋 변경이 시작된 단계는 안전하게 완료하거나 복구한 뒤 취소 결과를 반환한다. 프로세스 중단 후 미완료 복구 기록이 발견되면 새 적용보다 복구 검증을 먼저 수행한다. 재시도는 새 OperationId와 원래 작업 참조를 사용하고, 현재 원본 및 적용본 해시를 재검사한다. 외부 변경이 발견되면 오래된 백업으로 덮어쓰지 않고 RecoveryRequired와 충돌 경로를 표시한다.

## 5. 기능별 동작

### 5.1 ED-F01 — 전투 테스트 콘솔

전투 상태를 만드는 기능과 게임을 진행하는 기능을 제공한다.

- 시작 조건: 웨이브, 플레이어별 유닛·배치·재화·강화·보장 카운터, 테스트 시드.
- 상태 주입: 일반 적 99/100/101개, 보스 HP 1, 특정 상태이상, 보드 가득 참, 잠긴 제작 재료.
- 실행 제어: 시작·종료·재시작, 로컬 테스트 일시정지, 한 논리 스텝 진행. 배속은 논리 스텝 간격을 유지하는 실행 방식을 검증한 뒤 추가한다.
- 관찰: 웨이브·경과 시간·적 수·과밀 누적 시간·보스 HP·보드 버전·재화·보장 카운터·명령 결과.
- 결과: 실행 ID, 실패 판정 이유, 피해·상태이상 기록, 사용 데이터·시드·명령 로그.

`20웨이브부터 시작`은 두 가지 의미를 구분한다. **초기 상태 프리셋**은 정의한 보드·재화·적 상태로 새 상황을 만든다. **스냅샷 복원**은 실제 전투에서 저장한 잔여 적·타이머 등을 복원한다. 앞선 웨이브를 실제로 플레이한 것처럼 보상을 임의 누적하지 않는다.

첫 버전은 초기 상태 프리셋을 지원한다. 중간 전투 스냅샷은 자동화 문서의 [공유 실행 계약](AUTOMATION.md#shared-test-contract)이 구현된 이후 추가한다. 시드 하나만 저장한 프리셋을 완전한 전투 복원으로 표시하지 않는다.

재화·유닛 주입은 테스트 준비 단계에서 사용한다. 준비가 끝난 뒤 소환·합성·판매 등의 행동 검증은 실제 게임 명령 처리 경로를 사용한다. 온라인 일반 매치에는 일시정지·상태 주입을 제공하지 않는다.

### 5.2 ED-F02 — 웨이브 에디터

1~30웨이브를 목록과 타임라인으로 표시한다. 기본 편집 항목은 제한 시간, 생성점별 적 수, 스폰 프로파일, HP, 보스 종류, 골드·별조각 보상이다.

- 수식 기반 생성 구간과 개별 웨이브 예외값을 구분하고, 어떤 값이 최종 적용되는지 표시한다.
- 첫 버전의 등장 시각 편집은 런타임이 지원하는 생성 구간·간격만 노출한다. 임의의 개별 스폰 타임라인은 데이터 계약과 실행기의 확장이 선행되어야 한다.
- 현재 기획의 보스 웨이브 10/20/30에는 보스 2개와 새 일반 적 0개를 표시한다. 이전 웨이브의 잔여 적은 별도 항목이다.
- 적 수·HP·보상 곡선은 입력 데이터의 변화다. 실제 승률이나 전투 난이도의 측정 결과처럼 표시하지 않는다.
- 웨이브 복제·여러 행 일괄 수정·수식으로 되돌리기를 지원한다. 총 웨이브 수나 종료 규칙 변경은 관련 게임 규칙의 변경으로 취급한다.
- `이 웨이브 시험`은 선택한 초기 프리셋과 함께 실행하고 결과를 해당 데이터 버전에 연결한다.

참조: [전투·웨이브·승패](../design/BATTLE.md), [데이터 명세](../DATA_SCHEMA.md).

### 5.3 ED-F03 — 유닛·스킬 에디터

유닛 등급, 공격력, 공격 간격, 사거리, 피해 타입, 스킬 참조를 편집한다. 스킬 상세에는 발동 조건, 쿨다운·공격 횟수, 범위, 대상 수, 지속 피해, 둔화·스턴·방어 약화·오라를 노출한다.

- 선택한 효과 타입에 해당하는 필드만 활성화하고, 단위를 초·cm·비율 또는 퍼센트로 명시한다.
- 단일 표적·다수 적·보스·지원 조합 프리셋에서 실제 전투 로직으로 실행한다.
- 기본 공격력/공격 간격으로 계산한 참고 DPS와 실전 측정 DPS를 구분한다.
- 지원 유닛은 피해량 외에 버프 적용 시간·둔화 유지 시간·조합 전체 피해 변화로 평가한다.
- 스택 3개는 실제 개체 3개의 타이머로 실행한다. 공격력 3배짜리 개체로 대체하지 않는다.
- 기본 공격·자동 스킬·지속 피해를 분리해 기록하고, 비교 시 표적 방어력·저항·배치·측정 시간을 고정한다.

참조: [수호자·스킬](../design/UNITS.md), [전투 계산](../design/BATTLE.md).

### 5.4 ED-F04 — 소환·경제·제작 에디터

골드·별조각 소환 프로파일, 보장 조건, 가격 증가·상한, 판매금, 강화 비용, 재료 교환 비용·한도, 신화 레시피를 편집한다.

- 확률은 사용자가 읽는 퍼센트와 저장되는 정수 가중치를 함께 표시한다. 현재 저장 기준 합계는 10,000이다.
- 일반 추첨과 보장 추첨의 분포를 나눠 표시한다. 보장 상태별 결과와 카운터 변화를 미리 확인한다.
- 레시피는 재료 유닛에서 결과 유닛으로 이어지는 연결도로 표현하고, 존재하지 않는 ID·잘못된 등급·수량을 검출한다.
- 비용 비교에는 평균·중앙값·분위수와 미획득 비율을 표시한다. 정해진 횟수 안에 신화를 얻지 못한 실행도 결과에 포함한다.
- 합성·제작의 보드 공간 부족과 재료 잠금을 시험할 수 있게 한다.

분포 계산과 반복 실행은 [자동화 기능 설계](AUTOMATION.md)의 AT-F03을 호출한다. 에디터에 별도 경제 계산 공식을 복사하지 않는다.

### 5.5 ED-F05 — 보드·경로 편집 및 분석

선택한 프로파일의 보드 차원·공용 순환 경로·생성점을 읽어 표시한다. 기존 4×3은 자체 초안이며 원작 공개 화면의 6×3 관찰과 차이가 있어 도구 상수로 고정하지 않는다. 원작 좌표 계약 확정 후 해당 프로파일을 갱신한다. 칸 위치·간격·경로 점·생성점 위치를 조정하고 사거리·오라·적 체류 구간을 겹쳐 본다.

- 경로의 닫힘·길이·생성점 범위·보드 겹침을 검사한다.
- 각 플레이어 시점에서 카메라가 180도 회전해도 화면 선택과 서버 CellId가 일치하는지 확인한다.
- 사거리 도달 여부와 적 이동 시간을 보여준다. 정적인 범위 그림을 실제 공격 횟수로 단정하지 않는다.
- 모바일 화면 비율별 경로 가시성과 SafeArea를 미리 본다. 실기기 터치 검수는 별도로 수행한다.
- 첫 버전은 기존 칸 수와 ID 규칙을 유지하는 위치 편집으로 제한한다. 보드 차원 변경은 CellId·명령·저장·UI 계약을 함께 확장한 이후 지원한다.

참조: [전장·배치·모바일 UI](../design/BOARD_UI.md).

### 5.6 ED-F06 — 유닛 외형 연결 도구

UnitId → VisualId → 시각 DataAsset의 연결을 조회하고 메시·AnimBP·아이콘·소환/공격/합성 VFX를 지정한다. 관련 에셋 누락과 잘못된 타입을 검출한다.

미리보기에는 유닛 회전, 공격·스킬 연출, 스택 배치, 낮은 VFX 설정을 포함한다. 시각 연결을 바꿔도 피해 판정 시점과 경제 규칙이 달라지지 않아야 한다. 밸런스 표에 무거운 메시를 직접 연결하는 대신 기존 [시각 데이터 분리 방향](ARCHITECTURE.md)을 따른다.

## 6. 구현 구성 제안

| 구성 | 책임 | 경계 |
|---|---|---|
| Editor 전용 모듈·패널 | 화면, 선택, 편집 초안, 실행 취소, 에셋 연결 | 배포 게임의 일반 사용자 기능과 분리 |
| 데이터 편집·적용 서비스 | 원본 저장, 생성, 임포트, 검증 결과 통합 | UI 없이도 자동화 실행기가 호출 가능 |
| Development 테스트 인터페이스 | 테스트 세션 생성, 초기 상태 주입, 상태 조회 | 서버가 상태를 적용하며 Shipping에서 진입점 제거 |
| 실제 게임 규칙 | 소환·경제·보드·전투·승패 판정 | 에디터·봇·자동 테스트가 같은 구현 사용 |
| 자동화 실행기 | 시나리오 실행, 로그·지표·실패 증거 수집 | 에디터와 명령행에서 공통 계약 사용 |

내부 패널의 첫 구현은 UMG 기반 [Editor Utility Widgets](https://dev.epicgames.com/documentation/en-us/unreal-engine/editor-utility-widgets-in-unreal-engine)를 활용할 수 있다. 해당 기능은 에디터 UI용이며 공식 문서상 Beta다. 에셋 검사는 사용자 규칙을 지원하는 [Data Validation](https://dev.epicgames.com/documentation/en-us/unreal-engine/data-validation-in-unreal-engine)과 연결한다. 세부 모듈·API는 실제 설치된 UE 버전과 프로젝트 구조 확인 후 확정한다.

## 7. 구현 순서와 산출물

| 단계 | 구현 범위 | 확인 가능한 산출물 |
|---|---|---|
| E0 — 연결 기반 | 게임 데이터 로드 확인, 편집 원본 이관 설계, 테스트 인터페이스 | 원본→생성→임포트 값 비교와 테스트 세션 생성 |
| E1 — 첫 사용 버전 | 네 탭, 초기 상태 프리셋, 웨이브·유닛 편집, 검증 결과 | 보스 테스트 상황을 저장하고 수치 변경 전후 재실행 |
| E2 — 밸런스 확장 | 스킬 상세, 경제·레시피, 반복 실행 연계, 결과 비교 | 동일 조건의 시드 묶음으로 변경 영향 확인 |
| E3 — 제작·재현 확장 | 중간 스냅샷, 보드·경로, 시각 에셋 편집 | 실패 상황 복원과 배치·연출 제작 흐름 |

전투 콘솔은 게임의 준비된 인터페이스부터 연결하고, 데이터 편집은 원본 경로가 정리된 항목부터 추가한다. 이 단계는 계획이며 담당자 배정·작업 착수·완료를 뜻하지 않는다.

## 8. 완료 조건

아래는 구현 후 실행할 검수 기준이다. 현재 실행 결과가 아니다.

| ID | 조건·행동 | 기대 결과 |
|---|---|---|
| ED-AC01 | 테스트 프리셋을 저장하고 창을 다시 열어 불러오기 | 두 플레이어의 보드·재화·웨이브·시드 설정이 보존됨 |
| ED-AC02 | 유닛 공격력 수정 후 저장·임포트·시험장 실행 | 원본·생성물·게임 로드 값이 일치하며 결과에 데이터 해시 기록 |
| ED-AC03 | 확률 합계 오류 또는 없는 SkillId 입력 | 필드별 오류 표시, 적용·실행 중단, 이전 적용본 보존 |
| ED-AC04 | 편집 후 취소 또는 다른 사람의 원본 변경 발견 | 취소 시 원본 불변, 충돌 시 덮어쓰기 없이 비교 표시 |
| ED-AC05 | 여러 에셋 임포트 도중 실패 | 실패 단계 식별, 부분 적용 상태의 실행 차단, 복구·재시도 가능 |
| ED-AC06 | 20웨이브 프리셋으로 새 실행 | 명시한 초기 상태만 적용되고 앞선 보상·잔여 적을 임의 생성하지 않음 |
| ED-AC07 | 데이터 버전이 다른 중간 스냅샷 복원 | 호환 검증 실패 사유 표시, 불완전한 복원으로 실행하지 않음 |
| ED-AC08 | 일반 매치 또는 Shipping에서 테스트 명령 접근 | 테스트 상태 주입·시드 지정·일시정지 진입점 사용 불가 |
| ED-AC09 | 지원 유닛 포함 시험장 결과 확인 | 단순 DPS와 조합 기여 지표·측정 조건을 구분해 표시 |
| ED-AC10 | 저장 직전 외부 원본 변경, 또는 적용 중 같은/다른 OperationId 요청 | 충돌·Busy 표시 또는 기존 결과 반환, 외부 변경·에셋을 중복 덮어쓰지 않음 |
| ED-AC11 | 원본 저장 성공 후 임포트 중단, 재시작 시 백업 복구 실패 | 저장/적용 상태 분리, RecoveryRequired 유지, 복구 검증 전 새 테스트 실행 차단 |

게임 규칙 검수는 [기존 QA 명세](../BACKLOG_QA.md)를 재사용한다. UI 성공 표시만으로 게임 규칙 검수를 통과 처리하지 않는다. 실행 증거는 [검수 기록](../production/TEST_RUNS.md)에 연결한다.

## 9. 구현 전 확인할 사항

- 현재 게임에서 실제로 준비된 전투·데이터·서버 인터페이스와 테스트 가능한 빌드.
- 편집 원본의 최종 형식과 위치. 초기 제안은 버전 관리 가능한 JSON 설정이다.
- 첫 시험장 맵과 대표 보스 프리셋. 첫 버전은 초기 상태 프리셋으로 충분한지 확인한다.
- 스킬별 계측 범위와 중간 스냅샷 지원 범위. 지원하지 않는 상태는 명시적으로 거절한다.
- 개발 작업은 [도구 작업 연결](AUTOMATION.md#tool-task-map)을 따른다. 담당자·일정은 미정이며 이번 문서 작성으로 착수하지 않는다.
